### P0-4 ✅ 量表提交无答案校验：空答卷=无抑郁，负数=重度抑郁

**位置**：`backend/app/api/routes/scales.py:22`、`:188`；`assessment_scales.py:36-61`

```python
class ScaleSubmit(BaseModel):
    answers: dict[str, float] = Field(default_factory=dict)   # 无必答校验、无取值范围

def _tier(self, total):
    for th in self.thresholds:
        if total >= th.get("min", 0) and total <= th.get("max", float("inf")):
            return th
    return self.thresholds[-1]        # ← 低于最小档时回落到"最严重"档
```

**实测结果**（同一成员，逐次清库后提交）

| 提交内容 | 总分 | 风险等级 | 结论 |
|---|---|---|---|
| `{}` 空答卷 | 0.0 | none | 无明显抑郁 |
| 只答 1/9 题 | 3.0 | none | 无明显抑郁 |
| 越界值 99 | 891.0 | severe | 重度抑郁 |
| **负数 -5** | **-45.0** | **severe** | **重度抑郁**（负分反而触发最严重档） |

**影响**
- 残缺答卷给出确定的"无抑郁"结论 → 假阴性
- 非法输入得到"重度抑郁" → 假阳性 / 无意义告警
- 这些错误记录随后会通过 `_should_push`（`scales.py:84-98`）**抑制 180 天内的复测提示**，并通过 12h 频控挡住正常复测——错误数据会排斥正确数据

**修复建议**：提交前校验题集完整且取值 ∈ 该题 `options[].value`，否则 422；`_tier` 对低于最小 `min` 的值返回最低档或报错，不要回落 `thresholds[-1]`。

**位置**：`backend/app/api/routes/reports.py:439-447`（metrics）、`:482-494`（lab）、`:497-513`（exam）、整段 `confirm_report` 无状态校验

```python
db.add(MetricRecord(
```

**影响**
- 收缩压 205 mmHg（高血压急症）、空腹血糖 22.5（危急值阈值 16.7）**均被存为「正常」**，红色危急横幅、待办提醒全部不触发——READM 主打的「危急值预警」在报告导入这条主链路上失效

4. confirm 增加状态机校验（仅 `pending` 可入档，否则 409）+ 幂等键或去重

### P0-7 ✅ 随机 / 餐后1h / 睡前血糖无参考范围 → 永远判为「正常」

**位置**：`backend/app/core/reference_ranges.py:25-47`（无这三个指标）

系统各处**都**在产生这三个指标名，唯独参考范围表没有它们：

- `backend/app/prompts/__init__.py:27` 要求模型输出 `random_glucose` / `postmeal_1h_glucose` / `bedtime_glucose`
- `backend/app/services/consultation.py:62` 明确规定「用户只说『血糖』且未明确状态时，**一律用 random_glucose**」
- `backend/app/services/extraction_rules.py:8-10` 把三者列入 `ALLOWED_METRIC_NAMES`
- `frontend/src/pages/MetricInput.tsx:57-61` 为三者配置了参考区间与危急阈值

**实测结果**（value 均取 15.0 mmol/L）

| 指标 | abnormal | critical | 参考范围 |
|---|---|---|---|
| `random_glucose` | **False** | **False** | [None, None] |
| `postmeal_1h_glucose` | **False** | **False** | [None, None] |
| `bedtime_glucose` | **False** | **False** | [None, None] |
| `postmeal_glucose` | True | False | [0.0, 7.8] |
| `fasting_glucose` | True | False | [3.9, 6.1] |

**影响**：**最严重的数据盲区**。由于提示词规定「只说血糖」→ `random_glucose`，**用户最常用的说法产生的正是那条永不判异常的记录**。血糖 15 mmol/L 会被存为正常，不进异常项、不进小结、不生成待办。同理 `bmi`、`weight` 也无范围（可接受），但三个血糖指标是明确的遗漏。

**修复建议**：为 `random_glucose`、`postmeal_1h_glucose`、`bedtime_glucose` 补 `ADULT_RANGES` / `CHILD_RANGES` / `CRITICAL_THRESHOLDS`；并加一条"前端/提示词声明的指标名必须都在参考范围表中有定义"的校验测试，防止再次漂移。

### P1-2 ✅ 单侧参考范围永不判异常（HDL 等）

**位置**：`reference_ranges.py:34`（`hdl_cholesterol: Range(1.0, None)`）、`metrics.py:39-46`（要求 `lo is not None and hi is not None`）

```
hdl_cholesterol = 0.4  ->  abnormal=False  critical=False  ref=[1.0, None]
```

只传单侧参考范围时更糟：`metrics.py:39` 的守卫是 `and`，只要客户端传了任一侧，**整个默认范围填充分支都被跳过**：

```
只传 reference_lower=40，值 300  ->  abnormal=False  critical=False
```

### P1-11 ✅ 调度器漏执行与重复执行

**位置**：`backend/app/services/summary_scheduler.py:54-69`（只在「当天」判定到期）、`:98-103`（查-插非原子）、`:95`（未过滤软删除成员）
